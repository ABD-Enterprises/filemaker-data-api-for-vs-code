# FileMaker failure modes: what goes wrong, what the extension does, what to change

Maintainer-facing catalogue. First written 2026-10-18 against `main` at `10359e9`, then re-baselined at `e2d4b28`. Non-certificate behaviour re-checked in source on 2026-10-20 at `6c73839` (1.6.0 plus subsequent fixes). **Code** below means this source review, not a new real-server run. Certificate rows (1.1–1.10, 1.12 and 1.27) and certificate-specific backlog entries retain their earlier evidence and are awaiting a separate review. Historical **Run** observations describe the original reproduction, not necessarily today's behaviour.
Scope: the Data API client (`extension/src/services/fmClient.ts`), its error pipeline
(`normalizeError`, `errorUx`), the connection wizard, the Explorer, the record editor, the script
runner, batch jobs, the AI tools, and proxy mode. Product code was not changed.

## How to read this

Every row says how sure we are:

| Mark | Meaning |
|---|---|
| **Run** | Reproduced on 2026-10-18 by running the real `FMClient` (bundled from `extension/src`) against scratch HTTP/HTTPS servers with generated certificates (Node 22.23, axios 1.20.0). The Node error codes and the text the extension shows are exact. The scratch servers imitate FileMaker responses; they are not FileMaker. |
| **Docs** | Stated on a current Claris or Node.js page (URL in [Sources](#sources)). |
| **Code** | Read in the source only (file and symbol). |
| **Unverified** | We could not check this against a real FileMaker Server or FileMaker Cloud. Treat as a hypothesis and test it on a real server before relying on it. Section 6 lists the real-server checks that would close the gaps. |

Verdicts: **good** (right behaviour), **acceptable** (works, could be nicer), **gap** (wrong, misleading or unsafe), **partial** (some requested behaviour is still missing).
New file references are repository-relative and name symbols rather than line numbers. The unchanged certificate rows retain older references relative to `extension/src/` (short service and utility names refer to those subfolders). Two documentation folders exist: `docs/` at the repository root (this file, `docs/security.md`) and `extension/docs/` (`extension/docs/USER_GUIDE.md`, `extension/docs/COMPATIBILITY.md`). Rows that name USER_GUIDE or COMPATIBILITY mean the `extension/docs/` copies.

## 0. The error pipeline today (read this first)

1. Direct Data API calls use `FMClient.requestWithAuth` / `requestNoAuth` in `extension/src/services/fmClient.ts`. Failures pass through `normalizeError` and become `FMClientError` values.
2. `normalizeAxiosError` in `extension/src/utils/normalizeError.ts` keeps FileMaker codes, Node `networkCode`, retryability and bounded, redacted details. Known connection errors use `describeNetworkFailure` in `extension/src/utils/networkErrors.ts`; timeouts name `filemaker.requestTimeoutMs`. `isDroppedMidResponse` describes an incomplete answer instead of presenting HTTP 200 as success. Non-axios errors keep their own message.
3. `showErrorWithDetails` / `selectErrorActions` in `extension/src/utils/errorUx.ts` offer **Retry** when the normalized error allows it, **Edit Profile** for credentials or configuration rather than privilege errors, **Open Settings** for timeouts, and details / bug-report actions. `Logger` in `extension/src/services/logger.ts` redacts output. Explorer load failures still use fixed placeholders (`FMExplorerProvider` in `extension/src/views/fmExplorer.ts`).
4. `toModelError` in `extension/src/ai/aiToolService.ts` scrubs the server address and caps text at 500 characters; it receives the shared error explanations.
5. A data-call HTTP 401 triggers one renewal and retry (`FMClient.requestWithAuth` / `renewRejectedSession` in `extension/src/services/fmClient.ts`). `recordSignInFailure` / `assertAutomaticSignInAllowed` pause rejected automatic sign-ins. Explicit **Connect** clears the pause and uses `isRetryableConnectError` in `extension/src/commands/index.ts` to retry only normalized retryable errors.

Proxy mode skips steps 1 and 5: see section 5.

## 2. Authentication

Documented behaviour: login is `POST .../sessions` with `Authorization: Basic <base64 account:password>`
and `{}` as the body [S2]; a **401 on login means wrong account or password**, a 401 elsewhere
means a missing or invalid token [S1]; the token "expires 15 minutes after the last call that used it"
and "each call that includes the token resets the session timeout counter to zero" [S3]; logging out is a
`DELETE` on the token [S4]. FileMaker business errors arrive as HTTP **500** with a code in
`messages[]` [S1], and the codes are listed in [S22].

## 3. Authorization: what an account can see and do

full access so that they do more than the caller [S13]; "if the calling account lacks a privilege for a step

for layouts, metadata and records do **not** say how restricted layouts, records or fields appear
[S20][S21][S10]. Treat everything marked Unverified below as a to-do for a real-server test with two
accounts (one full access, one read-only).

## 5. Direct mode versus proxy mode

| Topic | Direct | Proxy |
|---|---|---|
| Who talks to FileMaker | The extension (`FMClient` in `extension/src/services/fmClient.ts`) | A middleware the user runs; `ProxyClient.invoke` posts `{action, profile, payload}` to the configured endpoint (`extension/src/services/proxyClient.ts`). |
| TLS to FileMaker | `tlsAgent.ts` on the Data API URL | The proxy's concern. `tlsAgent.ts` applies to the **proxy endpoint** only (`proxyClient.ts:310`). Cases 1.1-1.12 apply to the proxy URL, not to FileMaker. |
| Session handling | 401 → one silent renewal; proactive refresh (`FMClient.ensureSessionToken` / `renewRejectedSession` in `extension/src/services/fmClient.ts`). | Proxy methods bypass `requestWithAuth`; `FMClient.createSession` uses `proxy-session` if the proxy returns no token. Real session expiry is the proxy’s job. |
| FileMaker error codes | Parsed from the body by `parseDataApiEnvelope` / `normalizeAxiosError` (`extension/src/services/responseGuard.ts`, `extension/src/utils/normalizeError.ts`). | `proxyFailure` rebuilds code, status, category and retryability from `ok: false` with `fmCode` / `status` (`extension/src/services/proxyClient.ts`). Older envelopes without `fmCode` still cannot support code-based handling. |
| Non-JSON replies | `parseDataApiEnvelope` rejects them (1.19). | `ProxyClient.invoke` rejects null, undefined and string replies with a plain error; legacy raw JSON object replies remain supported (`extension/src/services/proxyClient.ts`). |
| Unreachable FileMaker behind the proxy | n/a | Depends on the status the proxy returns; `Proxy request failed. (HTTP n)` |
| Credentials | Basic login with the stored password | The proxy API key is sent as `Bearer`; FileMaker credentials stay on the proxy |
| Who enforces privileges | FileMaker, per account | The proxy's FileMaker account; every extension user gets the same view unless the proxy maps users |

Implemented proxy contract: `{ ok: false, fmCode, status, message }`; `proxyFailure` in `extension/src/services/proxyClient.ts` rebuilds `FMClientError` with code / status (ADR-0001).

## 8. Troubleshooting by symptom (content for the user guide)

Written for people who run the extension, not for developers. "Ask your FileMaker administrator" lines are
what to put in the message to them. Messages are as the extension showed them when this catalogue was written;
the 1.4 fixes (PR #386) changed these rows as follows.

> **Status:** non-certificate rows re-checked at `6c73839`; certificate advice retains the earlier 1.4 review at `e61fb21`. They replace the 2026-10-18 rows ("today the message is the bare line"). Fixed since the first version of this table: the bare `Failed to create FileMaker session.` line, the `Cannot read properties of undefined` error, the unexplained 404, repeated failed sign-ins, the status bar always saying "connected", batch jobs stalling on a read-only account, and the missing way to trust a private server. Still open: the single-record script warning (S5), read-only controls (3.5), S6 (Explorer placeholders), N3, N7 to N10 (section 6), Claris ID sign-in for FileMaker Cloud, and everything marked **Unverified** until the real-server checks in section 6 are done. The user-facing text is in the user guide's [Troubleshooting](../extension/docs/USER_GUIDE.md#troubleshooting) section.

Trust and re-trust work on direct connections with all four `http.proxySupport` values, including `override`. A pinned connection refuses a required environment, VS Code or system/PAC proxy with `PIN_THROUGH_PROXY`; exclude the server from that proxy, or forget the pin and use a company CA file for a certificate that lists host names. CA-only profiles keep their previous proxy routing. Legacy allow-self-signed profiles go direct unless an environment proxy applies; behind one, their previous CONNECT route and possible host-agent replacement are unchanged.

| What you see | Most likely cause | What to do | What to ask the FileMaker administrator |
|---|---|---|---|
| "This server uses a certificate that is not trusted: FileMaker Server's default certificate is self-signed" | The server has FileMaker's built-in certificate (leaf `Claris Self Signed Certificate (Not for Production Use)`, issuer `Claris Root Authority`, no host names) | In the wizard, **Test Connection** shows **Trust this certificate for ...?** with subject, issuer, names, dates and SHA-256. Compare the fingerprint, accept, **Save Profile**. A CA file alone does not work for this certificate. | "Please install a certificate from a public authority, with the intermediate certificate, in the Admin Console (Configuration > SSL Certificate), and restart. Until then, what is the SHA-256 of the default certificate?" |
| "This server's certificate is not trusted by this computer. The certificate chain could not be verified ..." | The authority is not trusted here, or the server does not send its intermediate certificate | Trust the certificate by fingerprint, or, if the certificate lists the server's host names, set the company's root/intermediate PEM as the *Custom CA certificate file* under **Certificates (advanced)** (the message mentions the CA file only in that case) | "Please send the root and intermediate certificates as `.pem` and install the full chain on the server." |
| "The certificate of <host> is self-signed, and this computer does not trust it" | A self-signed certificate | **Trust this certificate…** after checking the fingerprint | "Please install a certificate from a public authority." |
| "The certificate of <host> lists no host names" | A certificate with no subject alternative names | Trust that one certificate, or use one issued for the name | "Which host name is the certificate issued for? Please issue one with that name." |
| "The certificate of <host> was not issued for that name" | You connected by IP address or by a name the certificate does not list | Use a name from the certificate | "Which host name is the certificate issued for?" |
| "The security certificate of <host> has expired" / "is not valid yet" | Server certificate out of date, or your computer's clock is wrong | Fix your clock first; if it is right, the server needs a current certificate | "The server certificate has expired - please renew and import it (Admin Console > Configuration > SSL Certificate), then restart." |
| "... is not the one you trusted for this connection" (**Review and re-trust**) | The server's certificate changed since you trusted it | If the administrator renewed it, review the new fingerprint and re-trust; otherwise stop | "Did you replace the server certificate? What is the new SHA-256?" |
| "The certificate you trusted for <host> has expired" | The pinned certificate ran out | Renew it on the server, then review and re-trust | "Please renew the certificate." |
| "A proxy is configured on this computer (HTTPS_PROXY, VS Code http.proxy, or a system/PAC proxy), and a trusted (pinned) server certificate cannot be checked through a proxy" | An environment, VS Code or system/PAC proxy applies to a pinned profile (`PIN_THROUGH_PROXY`), even if it also has a CA file | For an environment proxy, add the server's host to `NO_PROXY` and restart VS Code; for a VS Code or system/PAC proxy, exclude the server there so the pinned connection goes direct, or remove the proxy setting. The message states that a CA file does not help a pinned certificate; for a certificate with proper host names, forget the pin and set the CA file | "Is this server reachable without the company proxy? Can it be on the proxy bypass list?" |
| "This server's certificate failed VS Code's own certificate check (...), and this connection's certificate settings could not be applied on the environment-proxy route" | An untrusted pin/legacy request used the environment-proxy route while VS Code's networking patch was active; CA-only failures never get this message | Set `http.proxySupport` to `fallback` (Settings, search "proxy support") and test again; or install a public certificate on the server and choose Forget trusted certificate | "Can the server use a certificate from a public authority?" |
| "only offers old TLS versions" / "no TLS version or cipher is shared" | Old TLS on the server or proxy | Nothing to change in VS Code | "Please enable TLS 1.2 or newer." |
| "<host> does not speak https on that port" / "The connection ... was closed. The server may only accept https" | Wrong port, or `http://` against an HTTPS-only server | Check the Server URL and port | "Which port and scheme does the Data API use?" |
| "Nothing is listening on <host:port>" | Wrong port, or the server or Data API is stopped | Check the address and port | "Is FileMaker Server running with the Data API enabled?" |
| "The name <host> could not be found" / "could not be looked up right now" | Misspelling, VPN down, DNS not answering | Check spelling, VPN and network | "What is the correct host name?" |
| "Connecting to <host> timed out" / "no network route" | Firewall dropping traffic, server unreachable | Check network, VPN, address and port. Raise `filemaker.requestTimeoutMs` only for a slow server | "Is a firewall dropping traffic from my address?" |
| "The server did not return Data API JSON (...; HTTP n, ...)" | A web page, firewall, proxy or sign-in page answered, or the reply was empty or cut off | Open the Server URL in a browser; check base path and version | "Is a gateway or firewall rewriting requests to /fmi/data? Please allow my address." |
| "The server redirected the request" | A redirect (http to https, to another host, to a sign-in page) | Use the final address as the Server URL. Redirects are not followed | "Where should the Data API be addressed?" |
| `HTTP 404` with no FileMaker code | Wrong path or database, or the Data API is switched off | Check Server URL, base path `/fmi/data`, version `vLatest` and the database name | "Is the Data API enabled (Admin Console > Connectors > FileMaker Data API)? Is the database hosted and spelt as I entered it?" |
| `[212] Invalid user account and/or password` | Wrong account or password (the name is not case sensitive, the password is), or no `fmrest` privilege | Edit the profile and re-enter the password. The message lists the hosted databases if the name looks wrong | "Please confirm the account and reset the password; does my privilege set have *Access via FileMaker Data API* (fmrest)?" |
| "Sign-in is paused: FileMaker rejected the saved credentials (error 210-214) ..." | The saved credentials are inactive (210), expired (211), wrong (212), unknown (213) or locked (214) | Fix the account or password, then edit the connection and save, or **Connect** / **Test Connection**. Do not keep retrying | "My account is inactive/expired/locked - please re-enable it or reset the password." |
| `[956]` maximum sessions | No free Data API sessions | Wait; automatic sign-ins back off from 30 s to 5 min. **Connect** to try now | "Please disconnect idle Data API clients (Admin Console > Databases > Clients list > select the client > Disconnect)." |

On another server, external authentication | Do not keep retrying. 1703 pauses automatic sign-ins like 210-214 | "Does the Data API on our tenant accept an account name and password, or only Claris ID?" |
| `[802] Unable to open the file` | The file is closed or not hosted, or the privilege set lacks fmrest | Check the database name. Connect does not retry this | "Is the file open? Does my privilege set have the fmrest extended privilege?" |
