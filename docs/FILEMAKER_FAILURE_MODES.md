No server version was supplied. These facts apply to that server; older/other versions may use another HTTP status. ## Follow-up fixes for the headless QA findings

These are code and regression-test checks in this checkout; the real-server QA findings were supplied by the owner. This follow-up did not contact a server.

- Generated files go into their normal output folders. The client chooser starts at `.filemaker/generated/client`. Unmarked existing files require **Overwrite**, **Skip existing**, or **Cancel**, with the file names shown. AI context keeps other text outside its marked section and refuses project document names such as README.md. Generated FM Web layout pages carry an ownership marker; edited runtime template files are still skipped.
- Batch progress counts processed, successful and failed rows separately. A row error such as **1708** remains in the job's failure list with its record ID and code. Job details offer **Copy failures**. **Cancel Job** stops sending new work, waits for sent requests, and keeps partial results. It does not undo updates.
- Changing the wizard host or port clears its trusted certificate with a notice. An unchanged account keeps the stored password when the input is empty; it is shown only as a saved-password placeholder. Untested saves offer a visible **Save anyway** action unless policy requires a successful test.
- Query and script failures clear previous results and summaries. The page disables request buttons and the host ignores repeated requests while work is pending. Batch and delete commands allow one set of dialogs at a time.
- A dropped HTTP connection names the HTTP address and suggests checking its scheme and port; it does not assert that the server accepts only HTTPS. Test My Server lists each fact once.
- AI layout descriptions show an exact field name once and note repeats. AI record reads flag truncation when the tool's 20-row portal limit or FileMaker's reported portal total leaves rows out, and show returned and total counts when available. The Record Viewer and client support Load more for direct connections; this does not add portal paging to the AI tools.
- Record Viewer displays container URLs as text; it does not preview images. Added Layout Mode fields use the next free standard grid position, including labels, and the canvas grows. Edit Record by ID loads a supplied ID automatically.

## Diagnose a failed connection without signing in

Run **FileMaker: Diagnose Connection** from the Command Palette. Choose a saved profile or type an HTTPS server address without saving it. The report checks the address, DNS, port, certificate and VS Code network settings, then uses the extension's real connection to request `/fmi/data/vLatest/productInfo` without credentials. It shows PASS, WARN or FAIL, timings, the HTTP status and any FileMaker error code. Read **Most likely cause** for the next step.

A default Claris certificate can have no host names and no chain beyond the leaf. A CA file alone cannot fix the missing host name: confirm the full SHA-256 fingerprint with the administrator, then run Connect and choose Trust. The report prints the same uppercase, colon-separated fingerprint as the Trust dialog. Expired certificates should be renewed; certificates for another host should be replaced or reached using the correct name. A non-self-signed leaf sent alone can be issued directly by a private root authority, or the server may be missing an intermediate. Node's issuer errors and the leaf alone cannot distinguish these cases. Without a CA file configured, the report explains both: set the organization's CA file (**Certificate authority file**) in the profile for a private authority, or ask the administrator to install the full server chain for a public authority such as Let's Encrypt. Missing-intermediate advice comes first only when a CA file is already configured, the server sends only the leaf, and verification still fails with an issuer error. A missing intermediate is then likely, though the configured CA file could also be wrong. An older Allow self-signed profile already accepts any certificate; the report recommends switching to a confirmed fingerprint.

Trusted-fingerprint and older Allow self-signed profiles now work on direct connections with VS Code's default `http.proxySupport` setting: the extension uses a connection path VS Code does not replace. Custom CA profiles keep the same VS Code and system proxy routing as before. A trusted-fingerprint profile that needs an environment, VS Code or system proxy is refused with `PIN_THROUGH_PROXY`. Exclude the server in the proxy settings, or add it to `NO_PROXY` for an environment proxy. An older Allow self-signed profile behind an environment proxy keeps the previous proxy route; if VS Code replaces its certificate settings there, trying `http.proxySupport` set to `fallback` may help. An unpinned certificate's name, date and trust problems take priority over proxy hints. A certificate error in the Data API step points to certificate advice, rather than suggesting a web sign-in page.

The direct DNS, port and TLS probes may differ from a request through a proxy; the final Data API step uses the actual extension transport. Proxy profiles diagnose the FileMaker Server, not the middleware endpoint. A server path prefix is allowed and kept for the Data API request. No sign-in is attempted and no profile or trust setting is changed. Cancel stops further checks; each probe has an eight-second limit. Offline mode prevents probing. Like Connect, diagnosis uses user-confirmed saved profiles; it also allows a typed address in Restricted Mode and never loads a workspace template.

Diagnose Connection was checked on one real server on 2026-10-21: it had a valid Let's Encrypt certificate and used TLS 1.2. Every step passed; no sign-in was attempted.

Use **Copy for bug report** or **FileMaker: Copy Connection Diagnosis for Bug Report**, then answer **Hide the server address?**. The port and certificate details are omitted when hiding the address. Certificate subjects and issuers appear on one line each, and report lines have no surrounding quote marks. Reports pass through the extension's secret masking and never include credential fields, headers or cookies. Node does not expose the certificate format version here, so that check is explicitly skipped.

## Data transfer corrections (Unreleased)

CSV updates now keep text, spaces, dates and times as written. Number fields use layout field information once per job; unsafe or invalid numbers stay as text with a warning for each row. If field information is unavailable, values stay as text with a warning. Empty cells still leave fields unchanged. The Record Editor also keeps number-looking text in text fields.

CSV record columns come first, even with fields named only with digits. When layout fields clash with `recordId` or `modId`, record columns use reserved names with underscores; duplicate headers are refused. Updates also refuse older plain-column CSV files when the field list reveals a clashing layout field, before any record is edited. Column names and field names keep their spaces. Layout field information supplies CSV columns; without it, the first 100 records supply the columns and later unknown fields cause warnings. CSV note columns and JSONL notes say when related rows are missing.

Exports replace the chosen file only after success, using a temporary file in the same folder with owner-only permissions. Failure or cancellation removes the temporary file and leaves an existing file untouched. An empty successful CSV still writes headings. Excel-compatible CSV is optional; standard CSV has no byte-order mark. JSONL and semicolon-separated imports get a clear explanation.

These paths have local regression tests using stubs and temporary files. Real-server behavior still needs the outside-sandbox checks; these notes do not claim a new real-server run.

## 0. The error pipeline today (read this first)

1. Direct Data API calls use `FMClient.requestWithAuth` / `requestNoAuth`, delegated to `extension/src/services/fmClient/transport.ts`. Failures pass through `normalizeError` and become `FMClientError` values.
2. `normalizeAxiosError` in `extension/src/utils/normalizeError.ts` keeps FileMaker codes, Node `networkCode`, retryability and bounded, redacted details. Known connection errors use `describeNetworkFailure` in `extension/src/utils/networkErrors.ts`; timeouts name `filemaker.requestTimeoutMs`. `isDroppedMidResponse` describes an incomplete answer instead of presenting HTTP 200 as success. Non-axios errors keep their own message.
3. `showErrorWithDetails` / `selectErrorActions` in `extension/src/utils/errorUx.ts` offer **Retry** when the normalized error allows it, **Edit Profile** for credentials or configuration rather than privilege errors, **Open Settings** for timeouts, and details / bug-report actions. `Logger` in `extension/src/services/logger.ts` redacts output. Explorer load failures still use fixed placeholders (`FMExplorerProvider` in `extension/src/views/fmExplorer.ts`).
4. `toModelError` in `extension/src/ai/tools/errors.ts` (also available from `extension/src/ai/aiToolService.ts`) scrubs the server address and caps text at 500 characters; it receives the shared error explanations.
5. A data-call HTTP 401 triggers one renewal and retry (`requestWithAuth` in `extension/src/services/fmClient/transport.ts` / `FMClient.renewRejectedSession` in `extension/src/services/fmClient.ts`). `recordSignInFailure` / `assertAutomaticSignInAllowed` pause rejected automatic sign-ins. Explicit **Connect** clears the pause and uses `isRetryableConnectError` in `extension/src/commands/index.ts` to retry only normalized retryable errors.

Proxy mode skips steps 1 and 5: see section 5.

## 5. Direct mode versus proxy mode

| Topic | Direct | Proxy |
|---|---|---|
| Who talks to FileMaker | The extension (`FMClient` in `extension/src/services/fmClient.ts`) | A middleware the user runs; `ProxyClient.invoke` posts `{action, profile, payload}` to the configured endpoint (`extension/src/services/proxyClient.ts`). |
| TLS to FileMaker | `tlsAgent.ts` on the Data API URL | The proxy's concern. `tlsAgent.ts` applies to the **proxy endpoint** only (`proxyClient.ts:310`). Cases 1.1-1.12 apply to the proxy URL, not to FileMaker. |
| Session handling | 401 → one silent renewal; proactive refresh (`FMClient.ensureSessionToken` / `renewRejectedSession` in `extension/src/services/fmClient.ts`). | Proxy methods bypass `requestWithAuth`; `FMClient.createSession` uses `proxy-session` if the proxy returns no token. Real session expiry is the proxy’s job. |
| FileMaker error codes | Parsed from the body by `parseDataApiEnvelope` / `normalizeAxiosError` (`extension/src/services/responseGuard.ts`, `extension/src/utils/normalizeError.ts`). | `proxyFailure` rebuilds code, status, category and retryability from `ok: false` with `fmCode` / `status` (`extension/src/services/proxyClient.ts`). Older envelopes without `fmCode` still cannot support code-based handling. |
| Non-JSON replies | `parseDataApiEnvelope` rejects them (1.19). | `ProxyClient.invoke` rejects null, undefined and string replies with a plain error; legacy raw JSON object replies remain supported (`extension/src/services/proxyClient.ts`). |
| Unreachable FileMaker behind the proxy | n/a | Depends on the status the proxy returns; `Proxy request failed. (HTTP n)` |
| Credentials | Basic login with the stored password | The proxy API key is sent as `Bearer`; FileMaker credentials stay on the proxy |
| Who enforces privileges | FileMaker, per account | The proxy's FileMaker account; every extension user gets the same view unless the proxy maps users |

Implemented proxy contract: `{ ok: false, fmCode, status, message }`; `proxyFailure` in `extension/src/services/proxyClient.ts` rebuilds `FMClientError` with code / status (ADR-0001).

### Version collection decision

`/fmi/data/<version>/productInfo` is the Data API product-information route used by the extension. `<version>` is an API selector such as `vLatest`, not the installed FileMaker Server release. A literal `GET /fmi/data/version` is not evidence of an installed FMS version. The local Claris-reference inventory documents product name and formats, and explicitly labels the mock's extra `version` and `buildDate` as invented; the real response recorded here did not identify the FMS release. Therefore use the administrator-confirmed installed product version for the smoke matrix. An exact Admin API route, or any extra Data API version-discovery route, still needs verification against current Claris documentation when network access is permitted; none was verified in this offline change. Do not treat a mock product version as a completed smoke test.

### Follow-up safeguards (2026-10-21)

- Generated files accept a workspace reached through a symbolic link. Output components below the canonical workspace root must be real folders. This also covers FM Web project creation, runtime templates and bridge settings before any folders are created. All-layout type generation reports refusals instead of reporting zero generated files.
- Renewed sessions return without waiting for the previous session to close. Cleanup is best effort and never logs its token; a late request using the previous token retries with the replacement.
- Jobs keep complete batch lists in memory for the session. Recent jobs save all counts but at most 1,000 changed IDs, 1,000 untouched IDs and 1,000 failed rows, with a flag for each shortened list. Cancelled exports discard their temporary file and say “Cancelled; no file was written”.
